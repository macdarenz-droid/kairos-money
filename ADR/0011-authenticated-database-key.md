# Authentication-bound database key

The SQLCipher data key remains the existing random 256-bit value; the app PIN only verifies the app gate. Android Keystore holds a non-exportable AES-256-GCM wrapping key requiring strong biometric/device-credential authentication with a 60-second authorization window. Android Keystore uses the device's available backing; emulator hardware protection is not claimed. SQLCipher necessarily receives usable secret bytes in native process memory, so the wrapping key and the data key are distinct.

On first authenticated open, wrap the existing data key, decrypt to verify equality, then atomically save the wrapped value and remove the old vault entry. Never regenerate a missing wrapping key for an existing ciphertext. Authentication cancellation, lost keys, damaged ciphertext and storage failure cannot open the ledger. A cancelled prompt returns to the app lock. PIN replacement does not touch the data key or database ciphertext.

SQLite 6.0.2 independently persists its secret by default. A checksum-pinned Gradle transformation of its small UtilsSecret adapter disables secret persistence and installs a native memory-only secret provider. Upstream node_modules files are untouched; a dependency checksum mismatch fails the build. Before supplying the session key, synchronously remove and verify removal of SQLite's old saved copy. If interrupted between migration and removal, the next open retries cleanup before supplying any session key. No key is returned over the WebView bridge. Lock and activity destruction clear the session buffer; SQLCipher connections are closed by the existing lifecycle path.

Rejected: deriving a database key from the PIN; wrapping only the vault copy; enabling the plugin biometric setting without migrating old keys; leaving a persistent plugin copy during normal use. Existing backup encryption remains independent and is the recovery path after device-key loss/reset.

Device assertions inspect the non-exportable key and its authentication requirement, verify both legacy entries are absent, reject plugin secret persistence, verify expiration and that app-PIN verification does not refresh Android authentication, and verify reset removes both key aliases. The emulator uses its own disposable screen-lock PIN through the actual credential UI. Existing UI acceptance assertions are retained; the instrumentation runner handles the newly required native credential screen without editing the frozen import test. Native execution and backup-reset-restore acceptance must pass before S1 closes.
