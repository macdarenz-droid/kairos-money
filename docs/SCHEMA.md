# Current data model

Schema version: 2. Generated by `npm run schema` from canonical SQL migrations.

Money columns are signed INTEGER minor units, restricted to the JavaScript/native bridge exact integer range ±9,007,199,254,740,991. All arithmetic occurs in bigint. Positive is credit; negative is debit, including credit-account purchases. Confidence uses integer basis points (0–10000). JSON money is decimal integer strings when nested in JSON fields. Dates use ISO text; import normalization validates calendar dates against the statement period.

Drizzle models typed queries. SQL migrations enforce the complete constraints and foreign keys. Baseline rollback is destructive and explicitly guarded; subsequent migrations are reversible without deleting records. Coverage rows retain source provenance; union/gap functions exclude uncovered days from averages. transaction_sources retains every contributing batch, so shared transactions can survive a batch rollback.

## Import staging payloads

Reserved source row `__file__` contains a user-selected file as base64 in encrypted SQLite until extraction or discard. Reserved `__document__` contains the complete normalized document, account context, stated balances and optional payslip. Ordinary source rows contain editable normalized transactions and their issues. Committed documents remain available for deterministic rollback; these are not duplicate live ledger entries. Corrections can carry deferred merchant rules applied only at commit.

## Migration metadata

`_migrations(version INTEGER PRIMARY KEY)` is maintained transactionally by the migration runner. It is not financial data and is removed with the database during deletion.
